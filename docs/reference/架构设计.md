#### 数据库架构

**主数据库 (master.db)**

位置：`<userData>/data/master.db`（dev = `%APPDATA%\image-viewer\`，安装包 = `%APPDATA%\Image Viewer\`，由 `app.getPath('userData')` 解析）

```sql
-- 库列表
CREATE TABLE libraries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    root_path TEXT UNIQUE NOT NULL,
    status TEXT DEFAULT 'offline',
    last_scan TEXT,
    image_count INTEGER DEFAULT 0,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

-- 跨库收藏
CREATE TABLE favorites (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    library_id INTEGER NOT NULL,
    image_path TEXT NOT NULL,
    tags TEXT,
    rating INTEGER DEFAULT 0,
    note TEXT,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(library_id, image_path)
);

-- 收藏文件夹
CREATE TABLE favorite_folders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    library_id INTEGER NOT NULL,
    folder_path TEXT NOT NULL,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(library_id, folder_path)
);

-- 浏览历史（容量上限 500，插入时裁剪）
CREATE TABLE history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    library_id INTEGER,
    image_path TEXT,
    viewed_at TEXT DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (library_id) REFERENCES libraries(id)
);
CREATE INDEX idx_history_time ON history(viewed_at DESC);
```

**后续 Phase 新增表**（以 `database.ts` 建表/迁移代码为准，此处仅列清单）：

- `tags` / `image_tags` — 独立标签系统（Phase 3）
- `deleted_files` — 回收站删除历史（只读视图，Phase 1）
- `folder_covers` — 文件夹封面（Phase 6）
- `schema_version` + `jobs` / `job_items` / `edits` — **迁移 v2**（Phase 8）：后台作业持久化/断点续跑与非破坏性编辑版本链；重启时 running 作业批量转 paused

分库 `thumbs.db` 的 `images` 表另有 `phash` 列（DCT pHash，相似图查找，懒迁移 `migratePhashColumn()`）；`thumbnails.size` 支持 `preview`（1200px）档位（2026-09 媒体改造）。

**分库数据库 (thumbs.db)**

位置：`{库目录}\.ivlib\thumbs.db`

## 🤖 AI 插件子系统

Phase 8 交付（2026-09-18 骨架 + 遗留回填，2026-09-19 M1-M5 缺陷修复；设计见 [plans/ai-crawler-direction-2026-q4.md](../plans/ai-crawler-direction-2026-q4.md)）。总开关 feature flag `plugins.enabled` 默认 false，懒启动。

### 进程模型与通信

- **主进程侧**：`src/main/services/plugin-manager.ts`（统一装配入口）+ `src/main/plugins/plugin-host-process.ts`（`utilityProcess` 宿主，MessagePort 双向 RPC，`channel` 分域 + requestId 命名空间隔离；崩溃熔断 `MAX_CRASHES=3`，exit 监听带实例守卫）
- **Worker 侧**：`electron/plugin-worker.ts` + `src/main/plugins/worker-sdk.ts`（插件 `luuk.*` SDK 代理；`callMain` 逐调用显式透传自身 pluginId，无全局当前插件态）
- **主进程 SDK 实现**：`src/main/plugins/plugin-sdk-host.ts`（权限比对 `plugin.json` 的 `permissions[]`，越权拒绝；`edit.write` 强制 `assertWithinLibrary` + 输出根由 libraryId 反查）
- **加载器**：`src/main/plugins/plugin-loader.ts`（manifest 校验含 `requires.models[].sha256` 格式断言，状态机 idle→activated）

### 推理与资源治理

- **InferencePool**（`src/main/plugins/inference-pool.ts`）：ONNX 会话池，同名创建锁（并发双建仅建一个）、交互式插队、EP 回退 CPU（避开 CPU mem-arena 保留内存陷阱）、按 `lastUsedAt` LRU 驱逐与按插件销毁
- **MemoryMonitor**（`src/main/services/memory-monitor.ts`）：三级水位线；执行闸门双口径 —— 全应用聚合 RSS（yellow=1500/red=2500MB，可配置）与插件 Worker RSS（`memory.workerRedMB` 默认 500）任一 red 即拒；red 事件触发 `memory.evict`；阈值常量见 `src/main/services/plugin-manager.ts`
- **ModelManager**（`src/main/services/model-manager.ts`）：模型注册/流式 SHA256 校验/断点续传/`url→mirrorUrls` 回退；`verifyModel` 空 sha256 只校存在性不删文件；启动时回填已下载状态；`models.directory` 运行期读取
- **JobRunner**（`src/main/services/job-runner.ts`）：持久化后台作业（优先级/暂停/取消/断点续跑），收尾/取消/暂停三处统一 `pump()` 自泵拉起 pending 作业；多选 >20 的 AI 修图经 `jobsEnqueue` 入后台队列，handler 用 `getImagePath` 解析绝对 `paths`，`skipped` 归 failed（无假成功）
- **EditsService**（`src/main/services/edits-service.ts`）：非破坏性编辑输出（`_edits` 版本链，输出路径二次校验在库根内）

### 内置插件与构建管线

- `src/main/plugins/builtins/`：**autotone**（零模型全链路验证）、**matting**（u2netp，绝对量纲 alpha）、**upscale**（RealESRGAN-x4plus 分块，输出像素预算 40M 上限，超限抛业务错）；后处理均抽为纯函数模块 `post.ts`（可单测）
- 编译管线：`scripts/build-builtins.mjs`（esbuild 随 index.ts 打包，构建后 `verifyArtifacts()` 断言各 `<name>/index.js` 产物存在），输出 `dist-electron/plugins/builtins/`，经 `npm run build` / `build:dir` 随包

### 前端接线

`src/stores/pluginStore.ts`（op 可用性三条件判定 `getOpAvailability`：隐藏 vs 置灰“需下载模型”）、`SettingsPanel` 三 Tab（插件/模型/设置）、`file-ops/FileContextMenu` 动态菜单按可用性过滤/置灰、`JobProgressBar` 接入真实入队（toast“已加入后台队列”）。

## 🌊 媒体加载链路

> 本节描述 **2026-09 媒体加载性能改造后的目标态**（方案与实测记录见 [archive/媒体加载性能提升方案-2026-09.md](../archive/媒体加载性能提升方案-2026-09.md)）。代码已提交至 `fix/phase8-defects`（`6df2c18`）并经 `scripts/cdp-verify-media.mjs` 真机验证 29/29。

### media:// 自定义协议（流式 + HTTP 缓存）

**注册**：`electron/main.ts` 在 `app.whenReady()` 前 `registerSchemesAsPrivileged`（standard/secure/supportFetchAPI/**stream:true** —— 不加则 `<video>/<audio>` 按缓冲处理）。

**令牌机制**（`src/main/services/media-registry.ts`）：
- `token = HMAC-SHA1(sessionSecret, 资源标识).hex.slice(0,32)`；`sessionSecret` 每次启动 `crypto.randomBytes(32)` 随机（同会话内确定性——同一资源同一 URL，可命中 HTTP 缓存；对外不可预测）
- 资源标识：文件类 = `absolutePath|mtimeMs`；缩略图类 = `thumb|libraryId|imageId|size|contentVersion`
- 条目带 `kind`（`file` / `thumb`）；`resolveMediaEntry` 访问驱动 LRU 续期；容量 50000 / TTL 2h；确定性 token 使淘汰后重建得同一 URL
- 全小写 hex：不受 Chromium authority 强制小写化破坏（历史动机，见 [多媒体模块重构方案](../archive/多媒体模块重构方案.md)）

**响应行为**（`electron/main.ts` 协议处理器）：
- thumb 分支：`getThumbnailBytes`（LRU→DB→生成）取 WebP，`image/webp` + `Cache-Control: public, max-age=604800, immutable`
- file 分支：`fs.createReadStream` → `Readable.toWeb()` 流式（不再整包 `readFile`）；200 手动带 `Content-Length`；`ETag`(sha1 of mtime+size) + `If-None-Match` → 304；Range（含 suffix `bytes=-N`）→ 206 `Content-Range`
- 错误分支拆分 ENOENT→404 / 其它 IO→500 带日志；访问限制在已注册库路径内

**缩略图出口**（`src/main/services/image-service.ts`）：
- `getThumbnail/getThumbnails` 返回 `media://` URL 字符串（不再是 `data:image/webp;base64`，省 33% 体积与主进程同步序列化）；所有调用点赋值目标本就是 `img.src`，渲染层近零改动
- **falsy 契约**：无缩略图分支（缺元数据/音频/avi/mkv）返回空串 `''` 且不注册 token，前端占位判定依赖此契约
- `getThumbnailBytes(libraryId, imageId, size)` 供协议层；`getPreview`（1200px 懒生成，首次查看时存 `size='preview'`）
- LRU 缓存值统一 `Uint8Array`（消除字符串/二进制混装，`cache.ts` entrySize 按类型计算）；`getThumbnails` 批量接口保留仅作预热
- `loadFullImage`（整文件 base64 直传）已下线（IPC + preload + 白名单同步移除）

**生成限流与泄漏治理**（`thumbnailer.ts`/`scanner.ts`）：`sharp.concurrency(cores-2)`；ffmpeg 并发信号量 ≤2；固定 sleep 改轮询 + `rmSync` 重试 + `before-quit` 清理 `tmpdir/luuk-thumb-*`；扫描批次动态 + `process.memoryUsage().rss` ≥1.2GB 暂停闸门；缩略图批量写库事务化（WAL 独立评估中）。

**前端配套**：Lightbox 双图层渐进（preview 先上屏，原图 `img.decode()` 预热后交叉淡入，`src`/`key` 不变避免重挂载）；MasonryGrid 视口窗口化（rAF 节流 + 二分切片 + 稳定 key）；`useAdjacentPreload` 方向感知 ±3 + 视频首 1MB Range 预热；`ImageGrid` 向滚动方向前瞻预热 `getThumbnails`；网格 `<img decoding="async">`。

**历史**：早期 data URL 全量 base64（500MB 视频 → OOM）重构时废弃；`luuk-file://` 死代码已清理。

### 2. ImageService

**文件**：`src/main/services/image-service.ts`

**职责**：
- 图片元数据管理
- 缩略图缓存（LRU 200MB）
- 缓存 Key 格式：`${libraryId}-${imageId}`
- **媒体类型判断**：`getMediaTypeFromPath()` 基于文件扩展名（比数据库 `media_type` 更可靠）

**使用示例**：
```typescript
const images = await ImageService.getInstance()
  .getImages(libraryId, options);
// 返回的每个 image 包含 mediaType: 'image' | 'video' | 'audio'
```

**媒体类型判断逻辑**：
```typescript
private getMediaTypeFromPath(relativePath: string): 'image' | 'video' | 'audio' {
  const ext = path.extname(relativePath).toLowerCase();
  const videoExts = new Set(['.mp4', '.webm', '.mov', '.avi', '.mkv', '.m4v']);
  const audioExts = new Set(['.mp3', '.wav', '.flac', '.aac', '.ogg', '.m4a']);
  if (videoExts.has(ext)) return 'video';
  if (audioExts.has(ext)) return 'audio';
  return 'image';
}
```

### 3. ThumbnailerService

**文件**：`src/main/services/thumbnailer.ts`

**职责**：
- 使用 sharp 生成 WebP 缩略图，`sharp.concurrency` 限流（总核数-2）
- 支持多尺寸：small(120px) / medium(300px) / large(600px) / preview(1200px 懒生成)
- 视频帧 ffmpeg（并发信号量 ≤2，avi/mkv 短路），临时文件重试 + 退出清理（见媒体加载链路）

### 4. ScannerService

**文件**：`src/main/services/scanner.ts`

**职责**：
- 增量扫描（文件大小+修改时间双条件跳过，已有记录批量预载）
- 扫描进度事件通知；后台非阻塞扫描（library-scan-finished 广播）
- 缩略图批量预生成（动态批次 + RSS 闸门 + 事务写库）与 pHash 回填
- 性能：~4.5ms/张

### 5. CacheService

**文件**：`src/main/services/cache.ts`

**职责**：
- LRU 缓存淘汰机制，内存缓存上限 200MB（设置可调 100-1000MB）
- 值类型 `string | Uint8Array`，entrySize 按类型计算（2026-09 媒体改造后作为协议层 DB 读加速层）

## 🎨 核心组件

### 查看器

**外壳**：`src/components/ImageViewer.tsx` — 导航（←/→）、全屏（F11 沉浸式）、快捷键分发、媒体类型路由、信息面板（EXIF/直方图标签页）

**功能**：

- `MasonryGrid.tsx`：自适应布局 + 视口窗口化（rAF + 二分切片）

### 其他主要组件（Phase 2-8 陆续交付）
