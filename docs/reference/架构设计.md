### 2. 状态管理层 (Zustand 5)

**职责**：全局状态管理

**Store 划分**（`src/stores/`）：

- `imageStore.ts` — 核心 store：库/图片/收藏/文件夹树/排序（视图设置已拆出）
- `audioStore.ts` — 音频播放状态：播放/暂停/seek/音量/波形
- `historyStore.ts` — 浏览历史：列表加载/记录/清空（乐观更新 + 去重）
- `searchStore.ts` / `tagStore.ts` / `similarStore.ts` — 搜索/标签/相似图
- `themeStore.ts` — 主题/强调色/密度（持久化到 settings）
- `selectionStore.ts` / `viewStore.ts` — 多选与视图布局（自 imageStore 拆出）
- `slideshowStore.ts` — 幻灯片（过渡动画/随机/播放列表/背景音乐）
- `index.ts` — 统一导出

详细的字段与 action 以代码为准（`src/stores/imageStore.ts`）。此处不再维护易过时的接口快照。

CREATE TABLE favorite_folders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    library_id INTEGER NOT NULL,
    folder_path TEXT NOT NULL,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(library_id, folder_path)
);

-- 浏览历史（容量上限 500，插入时裁剪）
CREATE TABLE history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    library_id INTEGER,
    image_path TEXT,
    viewed_at TEXT DEFAULT CURRENT_TIMESTAMP,

CREATE INDEX idx_history_time ON history(viewed_at DESC);

## 🔌 媒体加载策略

所有媒体类型（图片/视频/音频）统一通过 `getMediaUrl` IPC 返回 `media://TOKEN` URL，避免全量 base64 加载导致大文件 OOM。

### media:// 自定义协议（当前实现）

**注册位置**：`electron/main.ts` → `protocol.registerSchemesAsPrivileged`（standard/secure/supportFetchAPI），协议处理器 `fs.promises` 直读文件并支持 HTTP Range 请求（视频 seek 必需）。

**工作原理**：
1. 前端调用 `getMediaUrl` IPC → 后端将库路径内的文件映射为随机**小写 hex 令牌**，存入 `src/main/services/media-registry.ts`
2. URL 形如 `media://HEXTOKEN`，渲染进程通过 `<img>` / `<video>` / `<audio>` 或 fetch 加载
3. 协议处理器用令牌查表得到真实路径，直读文件流

**令牌机制动机**：Chromium 的 WHATWG URL 解析会对 URL authority 部分强制小写化，破坏 base64 编码的大小写敏感性；令牌全为小写 hex 不受影响（详见 [多媒体模块重构方案](../archive/多媒体模块重构方案.md)）。

**安全检查**：IPC 处理器限制访问范围在已注册库路径内；库路径从数据库读取时使用 `.trim().replace(/\r/g, '')` 清理不可见字符。

**支持的媒体格式**：
- 视频：mp4, webm, mov, avi, mkv
- 音频：mp3, wav, flac, aac, ogg, m4a

> **历史**：早期用 data URL 全量 base64（500MB 视频 → 667MB 内存，OOM），重构时废弃；`luuk-file://` 自定义协议为死代码已清理。

### 2. ImageService

**文件**：`src/main/services/image-service.ts`

**职责**：
- 图片元数据管理
- 缩略图缓存（LRU 200MB）
- 缓存 Key 格式：`${libraryId}-${imageId}`
- **媒体类型判断**：`getMediaTypeFromPath()` 基于文件扩展名（比数据库 `media_type` 更可靠）

**使用示例**：
```typescript
const images = await ImageService.getInstance()
  .getImages(libraryId, options);
// 返回的每个 image 包含 mediaType: 'image' | 'video' | 'audio'
```

**媒体类型判断逻辑**：
```typescript
private getMediaTypeFromPath(relativePath: string): 'image' | 'video' | 'audio' {
  const ext = path.extname(relativePath).toLowerCase();
  const videoExts = new Set(['.mp4', '.webm', '.mov', '.avi', '.mkv', '.m4v']);
  const audioExts = new Set(['.mp3', '.wav', '.flac', '.aac', '.ogg', '.m4a']);
  if (videoExts.has(ext)) return 'video';
  if (audioExts.has(ext)) return 'audio';
  return 'image';
}
```

### 6. 插件系统与 JobRunner（Phase 8）

**文件**：`src/main/services/plugin-manager.ts`、`plugin-loader.ts`、`job-runner.ts`、`model-manager.ts`、`memory-monitor.ts`、`edits-service.ts`、`src/main/plugins/plugin-registry.ts`、`electron/plugin-worker.ts`

**要点**：
- 插件跑在 `utilityProcess` 内，经 MessagePort RPC 与主进程通信；`PluginManager` 为统一入口（发现/加载/生命周期/executeOp），受 `plugins.enabled` 总开关控制
- **内置插件装载双路径契约**：内置插件由 `plugin-worker.ts` 启动时 `registerBuiltinPlugin(id, activate)` 静态登记；第三方插件按清单 entry 动态 import；内置插件 `entry` 必须写磁盘真实存在的文件名
- **JobRunner**：作业持久化于 jobs/job_items 表，支持断点续跑/优先级/暂停取消；`job_items.imageId` 在 Agent 发现作业中约定为 sourceId
- 配套：`ModelManager`（SHA256 完整性校验）、`MemoryMonitor`（三级水位线）、`EditsService`（编辑版本链）

### 7. Agent 体系（Phase 9）

**文件**：`src/main/services/agent/`（基座 + `decision/` 子层）、`src/main/ipc/agent-handlers.ts`

**要点**：
- **不是 LLM Agent**：本地规则 + 统计学习 + 可选 Jev 判断；所有判断统一走 `DecisionProvider` 接口，经 `DecisionRegistry` 置信度门控升级链（未达门控时**链尾优先**回落）
- **人在回路**：Agent 只产生 Proposal，用户确认后才触发下载入库；反馈经 `FeedbackAggregator` 叠加到画像 `learnedDeltas`
- **隐私护栏**：Jev 默认关闭，`privacy-guard.ts` 出站前按文本元数据白名单过滤；API Key 只回 `hasKey`，明文不下渲染进程
- **装配分层**：`jev-bootstrap.ts`/`crawler-bootstrap.ts` 纯 DI 可单测（不 import electron），生产接线在 `agent-handlers.ts`

### 8. 采集层 crawler（Phase 9 M3）

**文件**：`src/main/services/crawler/`

**要点**：
- 连接器二分：`web-http`/`web-browser`（网站主道）与 `pc-app`（MTProto/本地导入例外）；适配器 `buildRequests`/`parseResponse` 为纯函数禁网络
- 链路：信息源 → 适配器出 plans → `RequestExecutor`（per-host 闸门 + 频控退让 + robots）→ 下载器（.part 原子落盘/Range 续传/SHA256）→ `Intake` 三级去重（url_hash→file_hash→pHash）入库 + sidecar → `RecommendScorer` 打分生成提案
- 双闸默认关：调度侧 `agent.enabled`，执行侧 `crawler.enabled`，任一关闭零对象零网络；scanner 排除 `_downloads`/`_edits` 目录防自我递归入库
