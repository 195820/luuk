# 多媒体模块重构方案

**版本**: 1.0
**创建日期**: 2026 年 6 月 22 日
**项目**: Luuk Image Viewer

---

## 一、背景与目标

### 1.1 现状问题

当前 `ImageViewer.tsx`（665 行）试图在一个组件中同时处理图片、GIF、视频、音频四种媒体类型，导致**每种都存在 bug**：

| 媒体类型 | Bug | 严重程度 | 位置 |
|----------|-----|----------|------|
| 视频 | seek bar 使用 `defaultValue` 不随播放更新 | P0 | `ImageViewer.tsx:624` |
| 视频 | 无 `onEnded` 回调，播完不触发任何动作 | P0 | `ImageViewer.tsx:459-488` |
| 视频 | mkv/avi/m4v 直接显示占位符，无降级方案 | P1 | `ImageViewer.tsx:474-488` |
| 视频 | 大文件全量 base64 加载，2GB 视频 OOM | P0 | `library-handlers.ts:362-394` |
| 音频 | 查看器内渲染 `<img>` 标签加载音频，永久 loading | P0 | `ImageViewer.tsx:459-504` |
| GIF | 暂停/播放按钮状态设置但从未应用到 `<img>` | P0 | `ImageViewer.tsx:645-665` |
| 图片 | fitMode 在旋转后计算错位（用 naturalWidth 而非旋转后尺寸） | P1 | `ImageViewer.tsx:242-248` |
| 通用 | 5 个 props 声明但未使用 | P3 | `ImageViewer.tsx:43-53` |
| 通用 | 幻灯片不等待视频播放完毕就跳转 | P1 | `App.tsx:318-338` |

### 1.2 根因分析

- **数据加载方式错误**：视频/音频使用 data URL 全量加载，而项目已有 `luuk-file://` 流式协议却是死代码
- **组件职责过重**：一个组件处理四种交互模式完全不同的媒体
- **store 拆分未完成**：`libraryStore.ts`、`uiStore.ts`、`favoriteStore.ts`、`folderStore.ts` 均为死代码，`imageStore.ts` 是上帝对象

### 1.3 目标

1. 修复所有 P0 级媒体播放 bug
2. 视频/音频改用 `file://` 协议，解决大文件 OOM
3. 引入专业开源库替换手写逻辑，降低维护成本
4. 分离媒体类型路由，各模块独立可测试

## 二、竞品调研结论

### 2.1 同赛道竞品

| 项目 | Stars | 定位 | 与 Luuk 差异 |
|------|-------|------|-------------|
| **Immich** | 104K | 自托管 Google Photos 替代 | Client-Server 架构，需部署服务端，定位完全不同 |
| **Hydrus Network** | 3K | 本地标签式媒体管理 | Python + PyQt，UI 老旧，无音频支持 |
| **ImageGlass** | 13K | 轻量图片查看器 | C# 原生，性能极好，但不支持视频/音频 |
| **nomacs** | 3K | 图片查看+对比 | C++ Qt，不支持视频/音频 |

**Luuk 差异化优势**：图片+视频+音频统一管理 + 虚拟滚动 + 自定义协议流式加载，在桌面多媒体管理器中定位独特。

- video.js（200KB+、12 依赖）对本地文件播放是杀鸡用牛刀
- 自定义控件可完全按需求设计（帧级导航、倍速、键盘快捷键）

- 零依赖、官方 React 支持（`useWavesurfer` hook）
- 1M+ 周下载量，社区活跃

## 三、架构方案

### 3.1 目标架构

```
现在（一个 ImageViewer 打天下）：
ImageViewer.tsx (665行，图片+GIF+视频+音频全塞一起)

改后（分离 + 专业库）：
MediaViewer.tsx          ← 外壳：导航、全屏、快捷键、媒体类型路由
  ├─ ImageLightbox.tsx   ← yet-another-react-lightbox（图片+GIF）
  ├─ VideoViewer.tsx     ← 原生 <video> + 自定义控件
  └─ AudioViewer.tsx     ← wavesurfer.js（波形可视化）
```

### 3.2 数据加载策略变更

| 媒体类型 | 现在 | 改后 |
|----------|------|------|
| 图片 | `loadFullImage` → data URL | 保持 data URL（图片通常不会太大） |
| 视频 | `getMediaUrl` → 全量 base64 data URL | **`file://` 协议直连** |
| 音频 | `getMediaUrl` → 全量 base64 data URL | **`file://` 协议直连** |

**关键认知**：`library-handlers.ts:383` 注释说"Chrome media pipeline does not support custom protocols"是对的，但**不需要自定义协议**。Electron 渲染进程可以直接用 `file:///D:/photos/video.mp4`，`<video>` 和 `<audio>` 元素原生支持 `file://` 协议。当前用 data URL 纯粹是过度设计。

### 3.3 组件职责划分

| 组件 | 职责 | 依赖 |
|------|------|------|
| `MediaViewer.tsx` | 外壳：导航（←/→）、全屏切换、快捷键分发、媒体类型路由 | 无新增依赖 |
| `ImageLightbox.tsx` | 图片/GIF 查看：缩放/平移/旋转/翻转/幻灯片 | yet-another-react-lightbox |
| `VideoViewer.tsx` | 视频播放：播放/暂停/seek/音量/倍速/帧级导航 | 原生 `<video>` |
| `AudioViewer.tsx` | 音频播放：波形显示/交互式定位/播放控制 | wavesurfer.js + @wavesurfer/react |

## 四、分阶段实施计划

### 阶段一：止血 — 修复 P0 Bug + file:// 加载（1-2 天）

**不引入新依赖，纯修 bug。**

| 任务 | 文件 | 说明 |
|------|------|------|
| 视频/音频改用 `file://` 协议 | `App.tsx`, `library-handlers.ts` | 删除 `getMediaUrl` 的全量读取，改为返回本地文件路径 |
| 修复视频 seek bar | `ImageViewer.tsx` | `defaultValue` → 受控 `value` 绑定 `currentTime` |
| 添加视频 `onEnded` | `ImageViewer.tsx` | 播完触发回调（幻灯片模式下自动前进，否则停止） |
| 修复音频在查看器的渲染 | `ImageViewer.tsx` | 音频类型不渲染 `<img>`，改为跳过或显示占位 |
| 缩略图缓存 Map 加上限 | `imageStore.ts` | `thumbnailCache` 加 LRU 淘汰或 size 上限 |
| 幻灯片等待视频播完 | `App.tsx` | 视频播放中暂停定时器，`onEnded` 后恢复 |

### 阶段二：音频升级 — wavesurfer.js（1 天）

| 任务 | 文件 | 说明 |
|------|------|------|
| 安装 wavesurfer.js | `package.json` | `npm install wavesurfer.js @wavesurfer/react` |
| 改造 AudioPlayer | `AudioPlayer.tsx` | 用 `useWavesurfer` hook 替换原生 `<audio>`，添加波形显示 |
| 音频文件改用 `file://` | `AudioCard.tsx`, `audioStore.ts` | 已经是 `file://`，确认无需改动 |
| 查看器内音频处理 | `MediaViewer.tsx` | 音频在查看器中显示波形界面而非 `<img>` |

### 阶段三：图片升级 — YARL（1-2 天）

| 任务 | 文件 | 说明 |
|------|------|------|
| 安装 YARL | `package.json` | `npm install yet-another-react-lightbox` |
| 创建 ImageLightbox | `ImageLightbox.tsx` | 用 YARL 替换 `react-zoom-pan-pinch`，启用 zoom/slideshow/thumbnails/fullscreen 插件 |
| 删除手写控制代码 | `ImageViewer.tsx` | 移除手动的 zoom/rotate/flip/fitMode 逻辑（YARL 内置） |
| 升级 GIF 控制 | `ImageLightbox.tsx` | GIF 暂停改用 canvas 方案或 `gifuct-js` 逐帧渲染 |
| 删除 `react-zoom-pan-pinch` | `package.json` | 移除不再需要的依赖 |

### 阶段四：架构清理（1 天）

| 任务 | 文件 | 说明 |

## 六、风险与注意事项

| 风险 | 缓解措施 |
|------|----------|
| YARL 自定义程度不够（需要旋转/翻转等特殊交互） | YARL 支持自定义 slide render，可在插件架构上扩展 |
| wavesurfer.js 大音频文件首次加载波形慢 | 使用 `backend: 'WebAudio'` + 预生成波形数据缓存到 thumbs.db |
| `file://` 协议在 Electron 中的 CSP 限制 | 确保 `webPreferences.webSecurity` 配置允许 `file://` 加载 |
| 删除死 store 可能有隐藏引用 | 删除前全局搜索 `useLibraryStore` / `useUiStore` / `useFavoriteStore` / `useFolderStore` 确认 |
