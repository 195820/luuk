## 一、归档测试用例执行

### TC-THUMB-004 跨库缓存隔离

| 项目 | 内容 |
|------|------|
| **前置条件** | 存在多个图片库（multi-library-1, multi-library-2） |
| **测试步骤** | 1. 浏览库 A 的缩略图<br>2. 切换到库 B<br>3. 观察缩略图内容 |
| **预期结果** | 库 B 显示正确的缩略图，不显示库 A 的图片 |
| **实际结果** | ✅ **通过**（2026-09-29）切库后 imageId 集合与缩略图 src 零重叠：overlapKeys=0、overlapThumbSrcs=0 |
| **备注** | 验证缓存 key 格式 `${libraryId}-${imageId}` 的隔离效果 |

### TC-THUMB-005 LRU 淘汰

| 项目 | 内容 |
|------|------|
| **前置条件** | huge-library 已扫描完成 |
| **测试步骤** | 1. 连续浏览 1000+ 张图片<br>2. 监控进程内存<br>3. 观察缓存淘汰日志 |
| **预期结果** | 内存稳定在 500MB 以内，旧缓存正确淘汰 |
| **实际结果** | ✅ **近似通过**（2026-09-29）huge-library 连续 10 轮滚动，主进程 RSS 稳定 200MB、渲染堆 17MB 无增长（< 500MB） |
| **指标记录** | 内存峰值：200MB（主进程 RSS，渲染侧 JSHeap 17MB） |

### TC-GRID-001 虚拟滚动性能

| 项目 | 内容 |
|------|------|
| **前置条件** | huge-library (7000+张) 已扫描 |
| **测试步骤** | 1. 快速滚动图片网格<br>2. DevTools 观察 DOM 节点数 |
| **预期结果** | 滚动流畅，DOM 节点数恒定（仅渲染可见区域） |
| **实际结果** | ✅ **通过**（2026-09-29）虚拟滚动生效：顶部 DOM 卡片 45，滚动 6 次采样 [70,45,45,45,45,45] 近似恒定 |
| **FPS 估值** | 未直接采样帧率；以滚动期/静置期 DOM 恒定 + 内存零增长作为流畅性代理指标 |

### TC-GRID-002 懒加载

| 项目 | 内容 |

### TC-PERF-001 千级图片加载

### TC-PERF-002 内存占用

| 项目 | 内容 |
|------|------|
| **前置条件** | 应用正常运行 |
