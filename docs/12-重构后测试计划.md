### 关键修复记录

1. **media:// 协议令牌化**：原方案用 base64url 编码路径嵌入 URL，但 Chromium 的 WHATWG URL 解析会对 authority 部分强制小写化，破坏 base64 大小写敏感性。修复为令牌映射方案：IPC 端生成随机 hex token 并缓存 `{token → filePath}`，协议处理器用 token 查表。URL 全是小写 hex，不受浏览器小写化影响。
2. **协议处理器直读文件**：用 `fs.promises.readFile` / `fs.promises.open` 替换 `net.fetch(file://...)`，显式支持 Range 请求（视频 seek 必需）。
3. **`protocol.registerSchemesAsPrivileged`**：注册 `media` 方案为 `standard/secure/supportFetchAPI/corsEnabled`，确保浏览器 API 可正常访问。
4. **视频尺寸自适应**（2026-06-22）：`.viewer-video` 原先 `width/height: auto` 叠加 `object-fit: contain` 导致视频按原始分辨率渲染且默认左对齐。修复为 `width/height: 100%` + `max-width/max-height: 100%` + `object-fit: contain`，视频自动适应窗口并居中；背景 `#000` 用于 letterbox 黑边。
