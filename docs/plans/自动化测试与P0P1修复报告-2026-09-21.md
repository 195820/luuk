## 二、缺陷修复详情

### 2.1 DEF-COVER-01（P0）：FolderTree 封面设置后侧边栏不刷新

**根因**
`FolderTree.tsx` 内部 `useState folderCovers` 只在 `useEffect(…, [libraryId])` 时刷新。ImageGrid / MasonryGrid / ImageViewer 三处"设为文件夹封面"直接调 `window.electronAPI.setFolderCover(...)` IPC 写后端，不通知 FolderTree 重新拉取。

**修复实施**

| 文件 | 变更 |
|---|---|
| `src/stores/folderCoverStore.ts` | 新建 113 行 Zustand store + `applyFolderCoverSet` / `applyFolderCoverRemove` 封装（写后端 + 同步 store）+ `window.__folderCoverStore` 测试钩子 |
| `src/stores/index.ts` | 导出 |
| `src/components/FolderTree.tsx` L44-71 | 移除本地 useState，改为订阅 store；`handleSetCover` / `handleRemoveCover` 使用 apply 封装 |
| `src/components/ImageGrid.tsx` L333 / `MasonryGrid.tsx` L307 / `ImageViewer.tsx` L215 | `setFolderCover` IPC 直调 → `await applyFolderCoverSet(...)` |

**回归（def-7-part2）**：真实 UI 右键图片 → 点击"设为文件夹封面" → 断言侧边栏 `<img>` 立即出现。
```
设置前: { hasImg: false } → 设置后（未切目录）: { hasImg: true }  ✅
```

### 2.2 DEF-CASCADE-01（P0）：Windows 反斜杠路径导致 favorites / history 级联失效

**根因**
`updateImagePath`（重命名级联）查询使用 forward-slash。但 `addFavorite / removeFavorite / removeHistoryByPath / setFavoriteRating / addHistory` 直接原样写入调用方传入的路径；如果调用方传反斜杠，同一条记录存在 `\` 和 `/` 两种格式，重命名 UPDATE 只命中其中一种。

**修复**：`src/main/services/database.ts` L338/L346/L353/L361/L640 五处入口统一 `imagePath.replace(/\\/g, '/')`。
注：`tagImages` (L696) 原本就已 map normalize，无需改。

**回归**：
1. MT-DATA-04 硬断言：`favorites.match === true`、`image_tags.length > 0`、`folder_covers.match` 三项全通过
2. DEF-CASCADE-01 专项：`toggleFavorite(id, 'set08\\photo071.jpg')` → DB 存 `set08/photo071.jpg` → batchRename 后 favorites 命中新路径

### 2.3 DEF-DIR-PATH（P1）：folder_path 字段同源问题

**根因**
`setFolderCover` / `removeFolderCover` / `updateFolderPath` 内部已 normalize，但 `addFavoriteFolder` / `removeFavoriteFolder` 两个写入口未处理，Windows UI 拼接的深层子目录（如 `set09\2024\day1`）会以反斜杠原样入库，`updateFolderPath` 前缀 LIKE 匹配不到。

**修复**：`src/main/services/database.ts` L489 / L498 两处入口添加 `folderPath.replace(/\\/g, '/')`。

**回归（新增 2 条 coverage 用例）**：

## 五、关键经验沉淀

1. **Playwright 双版本错配**：项目根 `playwright=1.63` 与 `@playwright/test=1.60` 不匹配，`npx playwright test` 会报 `Playwright Test did not expect test.describe() to be called here`。必须显式 `node node_modules/@playwright/test/cli.js test --config=tests/playwright.config.ts`。
2. **Electron `page.reload()` 会重置 Zustand 内存 state**：`imageStore.currentLibraryId` 回退到 `FAVORITE_LIBRARY_ID = -1`。测试中不 reload，改用 `window.__folderCoverStore.getState().refresh()` 测试钩子。
3. **IPC 响应 `{success, data}` 包装**：`createTag` / `getImageTags` 需解包 `res?.data?.id ?? res?.id`、`Array.isArray(res) ? res : (res?.data ?? [])`。
4. **测试幂等回滚**：任何硬断言失败会跳过清理代码。所有涉及 batchRename 的用例必须 `try/finally` 保证物理与 DB 回滚，并使用互不干扰的文件夹（MT-DATA-04 用 set07、DEF-CASCADE-01 用 set08、DEF-DIR-PATH 用 set06 + set09）。
5. **`test-results/` 目录被 Playwright 每次运行清空**：报告文件需放在 `docs/plans/` 等持久位置。

### 8.5 MT-DATA-02a 诊断发现
**现象**：首版将 `/absolute/outside/path.jpg` 列入“必须拒绝”的 5 个变体，实际返回 `rejected=false data={}`。

**定位**：`src/main/ipc/library-handlers.ts` L518 中实现为：
```ts
const absPath = path.join(library.rootPath, relativePath)
const resolved = path.resolve(absPath)
const libRoot = path.resolve(library.rootPath)
if (!isPathWithin(libRoot, resolved)) return { success: false, error: 'Access denied' }
```
**Windows 下 `path.join('D:/luuk/test-library', '/absolute/outside/path.jpg')` 将 `/absolute/...` 当普通段拼入**，与 POSIX 不同——结果仍在 libRoot 内，`isPathWithin` 自然放行；`readExif` 对不存在文件返回空对象。**非安全缺陷**。

**修复方式**：将测试拆为 `MUST_REJECT`（真实逃逸 5 项，均包含 `..` 或 `X:\`）与 `NO_LEAK`（`/absolute/...` 变体，允许成功但断言 data 不泄露外部内容）。同时提醒后续接手项目：若拓展到 Linux 发行，需确认 `path.join` 行为与 Windows 一致。

**运行结果**：**18/18 全通 (1.5m)**（原 14 + 新 4）。MT-DATA-01a 实测走 trash **失败** WARN 分支——headless 场景下 `trash` 包底层 `windows-trash.exe` 报 `Command failed`，用例降级为仅断 IPC 契约结构（软断言），真实回收站链路仍留给人工卡片。

**关键实现要点**：
1. **删除弹框抑制**：`fileOps.confirmBeforeDelete` 默认 true，headless 下原生 dialog 永久阻塞 → `electronApp.evaluate(({ dialog }) => { dialog.showMessageBox = async () => ({ response: 0, checkboxChecked: false }) })` 覆盖。
2. **autoScan 竞态规避**：`addLibrary(name, path, true)` 服务层已 fire-and-forget 触发 `scanLibrary`，测试再显式调用同一 libId 命中 `scanningLibraries` 守卫报“库正在扫描中” → 改为 `waitForTimeout(6000)` 等自动扫描完成。
3. **Windows SQLite 目录锁**：`.ivlib/thumbs.db` 被主进程持有期间 `fs.rmSync` 报 EPERM → `safeCleanupLib` 先 `removeLibrary`（触发 `closeThumbnailsDB`）再删目录；MT-EDGE-01a 因此放弃“删目录模拟离线”方案，简化为 offline→online 契约测试。
4. **IPC 响应三种格式并存**：`getAllTags`/`createTag`/`tagImages`/`getImageTags` 返回 `{success, data}` 包装需解包；`getFavorites` handler 映射为 camelCase（`imagePath`，断言用 `f.imagePath || f.image_path` 双兼容）；`addHistory`/`getHistory` 直接返回（history 为 snake_case）。
5. **收藏幂等写法（重要 pitfall）**：`--user-data-dir` 只影响 Chromium，**不影响 Electron 主进程** `app.getPath('userData')` → master.db 同机跨 spec 共享。`ui-interaction.spec.ts:MT-CORE-05` 已把 `set01/photo001.jpg` 加入收藏，`toggleFavorite` 是切换语义会反向取消（仅全 suite 复跑时暴露）。修复：先 `getFavorites` 查询，不存在才 toggle。
