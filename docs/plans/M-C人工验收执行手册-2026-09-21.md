### 6.1 已登记缺陷

#### [DEF-WORKER-ENVELOPE] utilityProcess 信封未解包导致 setEnabled 永久挂起
**等级**: P1
**发现日期**: 2026-09-22
**发现人**: 唐昊琳
**被测 ref**: `fix/phase8-defects` @ af96af8（信封修复随本轮合入）
**库/插件状态**: test-library 100+ / plugins.enabled=true
**复现步骤**:
1. 启用任一内置插件（`pluginsSetEnabled('builtin.autotone', true)`）
2. 等待 `setEnabled` IPC 返回 / UI 开关状态变化
**预期结果**: Worker fork→ready→收到 `plugin.load` RPC→回包→state=`activated`，开关点亮
**实际结果**: Worker 进程 PID 存在并发出 `ready`，但主进程 `plugin.load` RPC 被静默丢弃 → `setEnabled` Promise 永不 resolve → UI 开关无反应；headless 下曾被误判为「Worker 挂死」
**根因**: `worker_threads` 的 `parentPort.on('message')` 回调直接收 `{type,data}`，而 `utilityProcess` 的 `process.parentPort.on('message')` 回调收到的是**事件对象** `{data: msg}`；兼容层未区分端口类型直接用 `msg.type` 取值 → `undefined` → RPC 处理被跳过，且 `rpc()` 无超时 → 无限阻塞
**修复**:
1. `electron/plugin-worker.ts` 增加 `unwrapPortMessage(port, msg)`，按 `isUtilityPort` 判定正确提取消息体
2. `src/main/plugins/plugin-host-process.ts` 的 `rpc()` 增加可选 `timeoutMs`，关键路径 `plugin.load` 设 15s
3. 超时后 `loader.setState(pluginId,'idle','启用失败：RPC 超时')` 回滚，避免 UI 卡死
4. `src/main/services/plugin-manager.ts` 装配调整
**环境**: Windows / Electron utilityProcess / Node ABI 137(test) vs 143(Electron) / test-library
**验证**: 修复后 headless 真实 Worker `setEnabled` **162ms**→`activated`；v5 A1 组 8/8 全绿（PH8-05b/16b/16c/18/19/23/27/28），证伪老「headless Worker 挂死」结论
**修复状态**: ✅ 已修复（本轮 E2E 回归覆盖）
